# 指令控制台

> 本文写**设计理由**与取舍，不写教程。用法见包根 `README.md`。

## 一、分层与职责

```text
Command/    纯逻辑：特性 / 参数 / 扫描器 / 注册表 / 上下文 / 默认值   ← 可单测，不碰场景
Transport/  协议解析与格式化（纯逻辑）+ TCP 服务端（IO）
Host/       Unity 宿主：DebugCommandService（Service, ITickable）+ 内置指令 + 游戏内控制台
Editor/     编辑器侧：控制台窗口、文档生成、校验、向导、FangHub 页
```

每层**不做什么**，比做什么更重要：

| 层 | 不做什么 |
| --- | --- |
| `Command` | 不认识 TCP，不写 Console（要日志就传 `warn` 回调），不碰场景 |
| `Transport` | 不执行指令逻辑（只把行交给 `DebugCommandRegistry.Execute`），不碰 UnityEngine（除了日志） |
| `Host` | 不写 Unity 消息方法（主线程靠 `ITickable` 驱动），不做编辑器的事 |
| `Editor` | 不改运行时状态（除了文档落盘），不复制一份扫描逻辑 |

### 为什么扫描器与注册表分开

运行时（`DebugCommandService`）与编辑器文档生成器调**同一个** `DebugCommandScanner`。
两处参考实现里「文档生成器又扫一遍程序集」是两套逻辑，指令一多就必然漂移；这里只有一套，
所以 `list_commands` 的输出与导出的文档**永远一致**。

### 为什么主线程由 `Scope.Tick` 驱动

核心包的约定是「框架不写任何 Unity 消息方法，生命周期由使用方显式驱动」。
`DebugCommandService` 遵守它（只实现 `ITickable`），代价是**装了但没人 tick ⇒ TCP 静默不响应**。
这是本包最容易踩的坑，所以：

- `ping` 指令会报 `ticking`；
- FangHub 页的状态标签、编辑器控制台的顶部状态行都会显示「⚠ 没有 tick」。

宁可把失败摆到脸上，也不要一个不吭声的服务。

## 二、`DebugProjectSo` 字段与默认值

默认值全部集中在 `DebugCommandDefaults`；SO 的字段都种上了这些值，**清空某一项就回落到它**。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `_autoStart` | `true` | 进入游戏就监听 |
| `_listenAddress` | `127.0.0.1` | 必须是 IP；留白回落 |
| `_port` | `7777` | 1~65535；越界（含 0）回落 |
| `_consoleEnabled` | `true` | 是否建游戏内控制台 |
| `_consoleToggleKey` | `` ` `` (BackQuote) | 开关快捷键 |
| `_quickButtons` | 空 | 额外的快捷按钮；内置 3 个始终在前 |
| `_commandAssemblyNamePrefixes` | 空 | 空 = 只扫引用了本包的程序集 |
| `_categoryOrder` | 空 | 空 = 内置指令分类（`builtin`）在前、其余按名称排序 |
| `_docFolder` | `Docs` | 工程相对路径（相对工程根，不是相对 Assets） |
| `_docFileName` | `DebugCommands.md` | 总索引文件名 |
| `_docSplitByCategory` | `true` | 每个分类再单独出一个文件 |

### 回落规则集中在 `DebugSettings`（一处，不是三处）

服务、文档生成器、FangHub 页都要读「生效配置」。如果各自写 `project == null ? 默认值 : project.X`，
迟早会漂移。所以多了一个 `DebugSettings`：

```csharp
var settings = DebugSettings.From(project);   // project 为 null 时整套走默认值
```

**只看 `DebugSettings` 发现不了「填错」**——越界的端口已经被悄悄回落成 7777 了。
所以校验器特意去看 SO 的**原始值**（`DebugValidator.AppendConfigIssues`），这样才能报「端口 70000 越界」。

## 三、扫描范围：为什么默认不是「全部已加载程序集」

两处参考实现一个扫自身程序集、一个扫全 AppDomain。本仓库实测（Unity 6000.3.2f1，编辑器里 250 个已加载程序集）：

| 范围 | 耗时 | 扫到的指令 |
| --- | --- | --- |
| 全部已加载 | **3291 ms** | 7 条 |
| 只扫引用了本包的 | **0 ms** | 7 条（完全一致） |

为什么一致：C# 里写 `[DebugCommand]` 必须能解析到这个类型，所以使用者程序集**必然直接引用**本程序集。
唯一漏网的是「用 `TypeForwardedTo` 把特性转发出去」，实践中不存在。

所以默认走 `ScanReferencingAssemblies`；要全量扫，就自己传程序集列表给 `Scan`。
SO 的 `_commandAssemblyNamePrefixes` 是另一条路：非空时在全部已加载程序集里按前缀过滤。

### 签名不符会被抓到（包括「贴在非 static 方法上」）

扫描器**连实例方法一起枚举**。只枚举 static 的话，「把 `[DebugCommand]` 贴到非 static 方法上」
会变成静默失效——那正是本包要消灭的失败方式。多出来的实例方法没有特性，代价只是多几次特性查找。

## 四、怎么加一种传输

**不需要接口。** 加传输 = 写一个类持有 `DebugCommandRegistry` 并调 `Execute`：

```csharp
public sealed class MyTransport
{
    private readonly DebugCommandRegistry _registry;
    public MyTransport(DebugCommandRegistry registry) { _registry = registry; }

    public void Pump()   // 由你的驱动方调用
    {
        var request = DebugCommandRequest.Parse(ReadLine());
        var response = request.Ok
            ? _registry.Execute(request.Command, request.Args)
            : DebugCommandRegistry.Error(request.Error);
        WriteLine(DebugCommandProtocol.FormatResponse(response, request.Id));
    }
}
```

刻意**没有** `IDebugCommandTransport` 空接口：接口不解决当前任何问题，只增加一层间接。
HTTP / WebSocket / stdin 都是「新类 + 调 Execute」。

注意两点：

- **执行必须在主线程**（指令内可能碰 UnityEngine API）。TCP 服务端的做法是后台只入队、主线程 `Drain()`。
- 回写要带请求的 `id`（`DebugCommandProtocol.FormatResponse` 会原样回填；解析失败时也会尽力从原文里把 id 捞出来）。

## 五、怎么换上下文

指令拿服务的默认方式是 `ctx.GetService<T>()`，查找分**两段**：

1. 沿核心包 `Scope` 的解析链（自身 → `Parent`…）**向上**找；
2. 向上找不到，再从当前 Scope 起**广度优先向下兜底**（自身 → `Children`…）。

**找不到返回 null 而不是抛**（核心包 `Scope.GetService<T>()` 找不到会抛，而「还没进游戏就该返回 error」
是指令的常见场景，用不了）。

### 为什么要向下兜底

指令服务常装在**浅层**（系统层 / App 层），而它要用的服务往往在**更深的层**（场景层）。只向上找的话，
「装在系统层」就摸不到场景层的服务，只能把指令服务一路下沉到最深的那一层 —— 那是个很别扭的约束。

向下兜底用的是公开的 `Scope.Services` / `Scope.Children`，**零反射，核心包一行没动**。
它只在**当前 Scope 的子树**里找：场景里另外独立摆放的根 Scope 不在这棵树里，走不到（见 §七）。

同一类型在子树里命中多个时取**第一个**（广度优先顺序）并打一条 `LogWarning` —— 拿到哪个由层级顺序决定，
静默取第一个会让人误以为拿到的是自己想的那个。

默认上下文的 Scope 提供者是「宿主服务所在的 Scope」。想加业务快捷属性就继承：

```csharp
public sealed class MyDebugContext : DebugCommandContext
{
    public MyDebugContext(Func<Scope> scopeProvider) : base(scopeProvider) { }

    public BattleController CurrentBattle => GetService<BattleService>()?.CurrentBattle;
}
```

然后换工厂，**不用改包**：

```csharp
service.Registry.ContextFactory = () => new MyDebugContext(() => scope);
```

`DebugCommandContext` 还带着发起本次执行的 `Registry`——`list_commands` / `command_log` 这类元指令要用它。

## 六、命名空间为什么是 `Fang.Framework.CommandConsole`

包名、程序集、命名空间现在是一致的：`com.fang.framework.commandconsole` / `Fang.Framework.CommandConsole*` / `Fang.Framework.CommandConsole`。

**但不要把它改叫 `Fang.Framework.Debug`** —— 这是实测出来的坑：只要有任何一个命名空间叫 `Fang.Framework.Debug`，
在它**以及它的兄弟命名空间**里，`Debug.Log(...)` 都会编译失败：

```text
error CS0234: The type or namespace name 'Log' does not exist in the namespace 'Fang.Framework.Debug'
```

因为 `Fang.Framework` 里多了一个叫 `Debug` 的命名空间成员，简单名 `Debug` 就先解析到它、而不是 `UnityEngine.Debug`。
兄弟命名空间同样受影响（本包最初就是为了绕开它才叫 `Fang.Framework.Debugging`）。

**程序集名不影响**——命名空间查找只看命名空间声明，不看程序集名。

## 七、已知限制

- **Release 包被剥空**：命令层全部包在 `#if UNITY_EDITOR || DEVELOPMENT_BUILD` 里，
  发布包（Release）这段代码被剥掉。`DebugProjectSo` / `DebugQuickButton` 不加守卫（是数据资产）。
- **Editor 专用程序集里的指令只在编辑器侧可见**：放在 Editor 程序集里的 `[DebugCommand]` 打包后不存在。
  要进包就放运行时程序集。
- **依赖 `Scope.Tick`**：见 §一。没有 `Update()` 自泵兜底——那会绕开核心包的约定，且会掩盖「没人驱动」这个事实。
- **监听地址只接受 IP**：写主机名（如 `localhost`）会启动失败并给出明确错误。刻意不做 DNS 解析（会阻塞主线程）。
- **控制台是 IMGUI**：要换 Input System，继承 `DebugCommandConsole` 覆写 `IsTogglePressed()`。
- **文档目录是工程相对路径**：写绝对路径会被校验器报错，导出时也会拒绝写越界路径。
- **分类名会变成文件名**：非法字符被换成下划线，撞名时追加 `_2`、`_3`。
- **`Configure` 改扫描范围会重扫**：会清掉之前扫到的与手工 `Register` 的指令，所以手工注册要放在 `Configure` 之后。
- **向下兜底只在子树里找**：从宿主服务所在的 Scope 往下找，场景里另外独立摆放的根 Scope 不在它的子树里 → 走不到。
- **忘标分类的指令归 `system`**：`builtin` 是包内置指令的分类，`system` 是「没写分类」的兜底，两者刻意分开；忘标的那条会以 `system` 出现在筛选与文档里。

## 八、刻意没做的事

| 没做 | 为什么 |
| --- | --- |
| `IDebugCommandTransport` 接口 | 不解决当前问题，只加间接层（§四） |
| `Update()` 自泵兜底 | 绕开核心包约定，还会掩盖「没人 tick」（§一） |
| SO 里的「资产清单」 | 指令是代码里的特性，扫出来的就是真相，没有需要登记的资产 |
| 分类枚举 / 常量表 | 分类是自由字符串（沿用 ui.kit 那次的教训），SO 只给排序 |
| 指令白名单 / 黑名单 | 扫描范围已经由程序集前缀 + 引用过滤表达，再加一层是重复 |
| 发布包里的指令 | 命令层整段被 `#if` 剥空，见 §七 |
