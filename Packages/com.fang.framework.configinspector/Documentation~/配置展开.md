# 配置展开

`com.fang.framework.configinspector` 的设计理由。实现只有一个抽屉加一个说明页，本文档记录的是**为什么是现在这个形状**。

## 一、这包解决什么

框架的配置是资产（`ConfigDataSo`），引用它的地方在别处 —— 预制体上的字段、场景物体的字段。默认检查器里只看得到一个资产名，想知道里面填了什么必须选中那个资产。

本包给这类字段加一个折叠箭头，展开后把被引用资产的属性**内联**画出来，可以直接改。

## 二、为什么独立成包，不进核心包

1. **它不是「一个窗口」，而是一次全局行为接管。** `[CustomPropertyDrawer(typeof(..., true))]` 一旦所在程序集被编译，所有命中类型的字段都改由它绘制。装核心包就顺手改掉全工程检查器外观，这不是核心包该做的决定。
2. **关不掉。** 见 §五 —— 既然「关闭」只能靠卸载，那就让「安装」成为使用方的选择。
3. **核心包定位是零依赖最小核心。** `目录规范.md` 里核心包 Editor 只放「扩展包分发 + FangHub」，不塞编辑器体验。
4. **仓库已有按需安装通道**：`packages.json` 索引 + FangHub「框架与扩展」页 + 每包独立 tag。多一个包的成本就是一套样板文件。

依赖方向不变：本包引用核心包（`Fang.Framework`）与核心包 Editor（`Fang.Framework.Editor`，为了挂 FangHub 页），核心包不引用本包。

## 三、为什么作用域收窄到 `ConfigDataSo`

参考实现（CastawaySurvival / LostMemories 的 `ScriptableObjectFieldDrawer`）是 `typeof(ScriptableObject), true` —— 全工程每个 SO 引用字段都接管，包括 `TMP_FontAsset`、URP 资产、Addressables 设置这些第三方资产的字段。

本包改成 `typeof(ConfigDataSo), true`：

- 只认框架自己的配置资产，不干扰第三方包的检查器；
- 语义干净：它服务的就是框架的配置模式（`Controller → Data → ConfigDataSo`）。

代价：声明成 `ScriptableObject` 或其它 SO 类型的字段不会有箭头 —— 这类字段本来也不是「框架配置」，不算损失。

## 四、两条渲染路径与递归守卫

Unity 检查器有 IMGUI 与 UI Toolkit 两套渲染路径，抽屉两条都实现（`OnGUI` / `GetPropertyHeight` 与 `CreatePropertyGUI`）。

**守卫是搬过来时必须补的东西。** 参考实现的 IMGUI 路径里 `s_expandedChain` / `MaxExpandDepth` 是**声明了没引用的死代码**，等于没有保护：

- `property.isExpanded` 会持久化。一个自引用的配置资产被展开过一次之后，**之后每次绘制都会无限递归 `GetPropertyHeight`** —— 直接栈溢出。
- 所以 `OnGUI` 与 `GetPropertyHeight` 都必须走同一套 `TryEnter` / `Remove` 配对：画子属性之前进链，`finally` 里出链。两个方法必须算出一致的高度，否则布局会错位。

守卫的两条判定：

| 情况 | 表现 |
| --- | --- |
| 被引用的资产已经在当前展开链上 | `(circular reference)` |
| 链长度已达 2 | `(max depth reached)` |

## 五、为什么不做运行期开关

不是不想做，是做不到干净：

- IMGUI 的 `PropertyDrawer.OnGUI` 里**调不到同类型的默认抽屉** —— 调 `EditorGUI.PropertyField` 会递归到自己。所以「不生效」没法表达成「转交默认绘制」。
- 硬做的话只能自己重写一遍默认绘制，或者留一个空实现让字段彻底消失，两种都不是好结果。

结论：**卸载包就是开关**。这也是 §二 让它独立成包的原因。

## 六、与参考实现（CastawaySurvival 初版）的差异

| 初版 | 现在 | 为什么 |
| --- | --- | --- |
| `[CustomPropertyDrawer(typeof(ScriptableObject), true)]` | `[CustomPropertyDrawer(typeof(ConfigDataSo), true)]` | 见 §三 |
| IMGUI 路径没有守卫（两个字段是死代码） | `OnGUI` 与 `GetPropertyHeight` 都走 `TryEnter` / `Remove` 配对 | 见 §四，自引用会栈溢出 |
| UITK 用 `OnObjectFieldChanged` 从父级反查内容容器（`parent.Q<VisualElement>(className: null)`） | 闭包直接持有 `content` 容器，引用变化由 `RegisterValueChangedCallback` 驱动 | `Q(className: null)` 不是有效的定位方式，反查不可靠 |
| UITK 的子 `SerializedObject` 存在抽屉实例字段上 | 存在 `CreatePropertyGUI` 的闭包局部变量里 | 抽屉实例会被 Unity 复用，多选 / 多元素时会互相串 |
| `GetFieldType` 用反射按 `propertyPath` 取字段类型 | 直接用 `PropertyDrawer.fieldInfo.FieldType`，取不到就退化成 `ConfigDataSo` | 反射那套对列表元素（`Array.data[0]`）拿不到类型；`fieldInfo` 是框架给的现成答案 |
| 没有编辑器页面 | 一个 FangHub 说明页 | 仓库惯例：带 Editor 的扩展包挂一页 |
