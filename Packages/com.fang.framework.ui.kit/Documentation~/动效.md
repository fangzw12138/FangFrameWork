# 动效

`com.fang.framework.ui.kit` 的动效设计：动效资产放哪、怎么和主题配合、运行时怎么播。

> **状态：v1 只定架构，不实现具体动效。** 已落地的是动效**资产类型**（`UiMotionSo`）与控件上的**槽位**（`KitButton.OnClick` / `OnLocked`）；播放器与 `MotionSlot` 枚举**留到动效落地时再加**（加字段、加枚举成员都是兼容变更，不破坏已发布的预制体）。

## 一、三层

```text
动效资产 UiMotionSo          纯数据：AnimationClip + 循环
     ↑ 引用
ButtonTokenSo → KitButton     token 把动效资产写进组件字段（编辑器期落盘）
     ↓ 运行时
播放器（以后加在 KitButton 内）  监听状态 → 在 root 上播 clip
```

- 资产是 `UiMotionSo`（`ConfigDataSo` 子类），**不是 token**：不参与匹配、不进 token 库、不出现在新建 token 的类型下拉里（那个下拉来自 `TypeCache.GetTypesDerivedFrom<TokenSo>()`，`UiMotionSo` 继承的是 `ConfigDataSo`）。
- `KitButton` 上有两个槽位字段，**只读引用（底图 / 按钮本体 / 图标 / 文字）+ 可写槽位**的划分见 `控件库.md` §四。
- 「空 = 不管」：token 里动效字段留空 = 不碰用户手配的动效。这条语义的存在就是为了保护动效。

## 二、动效资产为什么是 `AnimationClip`

| 方案 | 依赖 | 美术/策划能做吗 |
| --- | --- | --- |
| **`AnimationClip`** ← 选它 | 内置 | ✓ Unity **Animation 窗口直接做**、能预览、零依赖 |
| DOTween 序列 | DOTween | ✗ 它是**代码不是资产**，「拖拽动画资产」做不到（除非再写一层序列化，工作量大） |
| 自写关键帧插值 | 零 | ✗ 美术做不了，要自己造编辑器工具 |

选 `AnimationClip` 的决定性理由：**一条 clip 就能同时动多个节点**（多条曲线绑不同路径），所以「图标飞入 + 容器弹变形」是**一条** clip，不需要「步骤列表 + 角色枚举」那种结构。位置 / 缩放 / 旋转 / 颜色都能表达。

## 三、动效绑「结构」，主题绑「组件引用」

`AnimationClip` **按节点路径绑定**（曲线绑 `path = "IconSlot/Icon"`），而 token **跨预制体复用**。一条 `ButtonTokenSo` 若同时被「图标按钮」和「图标+文本按钮」用，clip 里写了 `path = "LabelSlot/Label"`，图标按钮没有那个节点，那条曲线就是**死曲线**（不报错，但什么也不动）。

**解法（成本最低）：约定「一条 `ButtonTokenSo` 只服务一种结构的预制体」。** v1 天然满足（三种按钮各配各的 token）。这不是巧合 —— 一个游戏里按钮的视觉样式就固定几种，每种结构固定。

推论，两条都要记住：

- 你改 Variant 的**节点名 / 层级**，动效就断（主题 token 不受影响，因为它的 target 是**组件引用**）。
- 包内预制体的**路径不能改名 / 移动**，否则消费者已导入的 Variant 断链（见 `定制与升级.md`）。

## 四、槽位

| 槽位 | 触发 | 状态 |
| --- | --- | --- |
| `Click` | 内部监听 `Button.onClick` | v1 只有字段，不播 |
| `Locked` | 外部 API | v1 只有字段，不播 |

`Hover` / `Show` 等以后加 —— **加枚举成员是兼容变更**。

## 五、播放机制（已实测）

v1 实测了两条路，**都可用**（本工程 Unity 6000.3.2f1，运行时实测，零报错零警告）：

| 方案 | 依赖 | 实测结果 |
| --- | --- | --- |
| **`PlayableGraph` + `AnimationClipPlayable`** ← 推荐 | 内置 | ✓ **裸 `Animator`（没有 `RuntimeAnimatorController`）可以作 `AnimationPlayableOutput` 的目标**；`graph.Evaluate(dt)` 立即把值写下去；root（`path = ""`）与子节点（`path = "Icon"`）都能动 |
| `AnimationClip.SampleAnimation(root, t)` + 自己驱动时间 | 内置 | ✓ **运行时可用**（不只是编辑器）；root 与子节点路径都能绑 |

推荐 `PlayableGraph` 的理由：可控 —— 循环 / 打断 / 变速 / 多 clip 混播都是图的能力；`SampleAnimation` 更适合「按时间点取值」而不是「播放」。

实测用的最小 clip：一条 `localScale` 曲线绑 root（`path = ""`）+ 一条 `localPosition.x` 曲线绑子节点（`path = "Icon"`），`graph.Evaluate(0.5f)` 后 root 缩放读到 1.5、子节点位置读到 25，符合预期。

## 六、运行时边界

`控件库.md` §一 写的是「主题由项目 SO 在**编辑器期**批量写入……不做运行时换肤入口」。动效**必须在运行时播**，所以本包是**双轨**的：

| | 什么时候 |
| --- | --- |
| 主题（颜色 / 字号 / 字体 / 图标 / 底图 / 交互态） | 编辑器期落盘 |
| 动效**资产引用**（`ButtonTokenSo` → 写进 `KitButton` 字段） | 编辑器期落盘 |
| 动效**播放** | 运行时 |

「不做运行时入口」指的是**换肤**（改主题值）；动效播放是另一回事，不在那条约束里。

## 七、动效要求预制体结构「为动效留位置」

`LayoutGroup` 会写子节点的 `anchoredPosition` 与尺寸，`ContentSizeFitter` 还会触发 Rebuild —— 都会覆盖动效。所以包内按钮预制体在容器和元素之间留了一层**槽位节点**（`IconSlot` / `LabelSlot`，挂 `LayoutElement`，尺寸由布局控制），动效作用在**内层**的 `Icon` / `Label` 上。

完整结构见 `控件库.md` §七 的「动效要求的结构」。你自己做 Variant 时**别把这一层删掉**，否则动效会被布局覆盖。
