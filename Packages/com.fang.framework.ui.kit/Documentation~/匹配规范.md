# 匹配规范

匹配 id（`MatchId`）是「匹配组件 ↔ token」之间的唯一键：匹配组件上每条条目写一个 `id`，token 库里**每条 token 自己的 `MatchId`** 写同一个字符串，两边靠它配对。

**它就是字符串，没有枚举、没有常量表。** 本文档只是**推荐命名**（方便你和以后接手的人对得上），不是校验规则 —— 你写 `Text/Title`、`我的/标题` 都合法，只要两边字符串一模一样。

## 一、形式

`id` 是**手填的字符串**（不是 SO 引用、也不是枚举）：`"Text/Title"`。

理由：轻，条目上只存一个字符串，不需要为每个 id 建资产；代价是拼错没有编译期保护 —— 所以**统一按下面的推荐命名走**，靠约定而不是靠代码兜底。

约定：

- 形状固定为 `<组>/<语义>`，两段都用 PascalCase，中间一个 `/`。
- **已发布/已在用的 id 不改名、不删**：改名等于把使用方的数据改坏。要调整就新增 id，旧 id 保留。
- 建议新 id 先记到本文档的组里，大家用同一套名字。

### id 存在哪

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| token 资产 | `TokenSo.MatchId` | **匹配 id 就落在这里**，它是「预制体端 ↔ token 库」的连接键 |
| 匹配组件条目 | `TokenMatchEntry.Id` | 同一个字符串，指向要用的槽位 |
| token 资产 | `ConfigDataSo.Id`（= 资产名） | 资产**自己的标识**，**绝不当匹配 id 用** |

`MatchId` 留空 = 这条 token **还没启用**：不参与匹配，校验只给一条提醒（不算问题）。

## 二、推荐命名

组只用来**归类**（文档分组、给人看），不限制能绑什么 token —— 一个 `Text/Title` 上同时绑字体 token 和颜色 token 是正常的。

### 文本

| id | 语义 |
| --- | --- |
| `Text/Title` | 主标题 |
| `Text/Subtitle` | 副标题 |
| `Text/Body` | 正文 |
| `Text/Caption` | 说明 / 注释小字 |
| `Text/Button` | 按钮文字 |

### 颜色

| id | 语义 |
| --- | --- |
| `Color/Primary` | 主色 |
| `Color/Secondary` | 辅色 |
| `Color/Background` | 背景 |
| `Color/Surface` | 卡片 / 面板表面 |
| `Color/Text` | 文字色 |
| `Color/Success` | 成功 |
| `Color/Warning` | 警告 |
| `Color/Danger` | 危险 |
| `Color/Disabled` | 禁用 |

### 图标

| id | 语义 |
| --- | --- |
| `Icon/Primary` | 主图标 |
| `Icon/Secondary` | 辅助图标 |

## 三、id 与 token 的关系

`id` 是**语义槽位**，token 是**一个属性的值**，两者是多对多：

- 一个 `id` 可以挂**多个 token**（token 库里每条 token 各写自己的 `MatchId`）。
- 一个 token **只写一个属性**（见 `控件库.md` 的 token 清单），所以「只改字体」就只放一个字体 token，字号 / 样式 / 行距完全不碰。
- 同一个 token 资产**只能挂一个 `MatchId`**（一个 token = 一个属性值 + 一个槽位）；要让两个槽位用同样的值，就复制一份 token。
- 同一个 `id` 上挂多个 token 时，**按 token 库里的顺序依次 `Apply`，后面的覆盖前面的** —— 这**不算错误、也不去重**；如果两个 token 写同一个属性，生效的是排在后面的那个。
- token 能不能用在某个 target 上，只看 token 的 target 类型（`TMP_Text` / `Graphic`），不靠 `id` 的组来卡。
