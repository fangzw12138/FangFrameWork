# 定制与升级

「包内只读」到底是什么意思、怎么定制、包升级后怎么迁。

## 一、「不要动包内」的机制原因

本包通过 Package Manager 安装时有**两种形态**：

| 形态 | 资产实际在哪 | 能改吗 |
| --- | --- | --- |
| **从 git / registry 装**（消费者） | `Library/PackageCache/com.fang.framework.ui.kit@<hash>/` | **不能** —— 升级会整目录替换，你的改动直接消失；`PackageCache` 也不该进版本控制 |
| **内嵌包**（包目录直接放在工程的 `Packages/` 下，随工程一起提交） | `Packages/com.fang.framework.ui.kit/` | **能** —— 它就是你工程的一部分（本仓库开发时就是这种形态） |

所以「包内只读」**只对消费者成立**。内嵌包随便改。

对消费者，正确的定制姿势是：**不动包内资产，改成你自己的资产**。

## 二、Variant 还是复制

| 做法 | 什么时候用 | 代价 |
| --- | --- | --- |
| **Prefab Variant**（推荐） | 改 icon / 加节点 / 调尺寸 / 覆盖子节点属性 | 包升级后**基预制体变了，你的 Variant 自动跟着变**（除非你覆盖了同一处） |
| **复制一份**（把包内 prefab 复制到工程里自己改） | 要大改结构、且不想要包升级的影响 | 与包**脱钩**，升级带来的改进你拿不到；包内节点改名时也不会断（因为已经没关系了） |

做 Variant：`Assets/` 里右键包内预制体 → `Create → Prefab Variant`，或直接把包内预制体拖进场景再拖回工程。

## 三、哪些属性归 token 管（会被覆盖）

「全体应用」会**覆盖**它声明的那几项。所以动手改之前先想清楚哪些是主题管的：

| 归 token 管（下次全体应用会被覆盖） | 不归 token 管（你随便改） |
| --- | --- |
| 文字：字体 / 字号 / 样式 / 行距 / 颜色 | 文字内容（`text`）、对齐、是否自动换行 |
| 图标：Sprite / 颜色 | 图标节点的位置 / 尺寸（布局与 `LayoutElement` 管） |
| 按钮：底图 Sprite、5 态 `ColorBlock` | 按钮尺寸、`LayoutElement` 的值、节点结构 |
| 动效槽位（`KitButton.OnClick` / `OnLocked`） | 其它自己加的组件 |

规则：**同一个属性要么归 token 管、要么你自己管，别两边都改。** 要「这个按钮不跟着主题走」，就别把它登记进项目 SO 的 `Prefabs`。

### 换底图时注意 9 宫格的 border

按钮底图是 `Sliced` 的 9 宫格。`Image` 在 `Sliced` 下的 `preferredWidth/Height` 等于 `border` 的四边之和，而按钮根上的 `ContentSizeFitter` 取最大值 —— 所以**底图 border 太大，按钮就压不到你要的高度**（改字号和 padding 都没用，实测踩过）。

包内底图 `border = 10`（四边和 20），配 32 高的按钮。换自己的底图时让 `border` 四边和小于目标高度；圆角半径也要 ≤ border，否则圆角会被切掉。

### 尺寸基线

包按 **PC 基线**做：参考分辨率 1920×1080 + `matchWidthOrHeight 0.5`，屏幕为 1080p 时 **1 UI 单位 = 1 像素**，所以包内默认值就是像素值 —— 标题 24 / 正文 16 / 说明 12 / 按钮文字 16、按钮高 32、图标槽 16×16。

要移动端量级就自己按比例放大（乘 1.5～2），或改 `CanvasScaler` 的参考分辨率（改参考分辨率等于整体缩放，字号值不用动）。

## 四、升级后示例（Samples）怎么迁

`Samples~/` 带 `~` 后缀，**Unity 不导入它**；Package Manager 的 Samples 导入是「**复制一份到 `Assets/`**」，所以：

- **已导入的副本不会被升级覆盖**，这是好事（你的改动不会丢），也意味着**你要自己决定什么时候拿新版示例**。
- 实测导入路径（Unity 6000.3.2f1）：

  ```text
  Assets/Samples/<包 displayName>/<包 version>/<sample displayName>/
  例：Assets/Samples/UI Kit/0.2.1/Controls Demo/
  ```

  **路径带包版本段** ⇒ 升级后导入会落到**新版本目录**，不会覆盖旧副本（旧目录会留在原地，你自己删）。

迁法：把旧目录里的**你自己的改动**（token 的值、Variant 的覆盖）搬到新目录；`Demo.unity` 建议重新打开新目录里的那份。

**你自己做的 Variant 不会因为包升级而断链**，前提是包内基预制体的**路径没变**。所以本包有一条约定：

> **已发布的包内 prefab 路径不改名、不移动。**（`Packages/com.fang.framework.ui.kit/Prefabs/*.prefab`）

改名 / 移动会让所有消费者已导入的 Variant 断链。真要调整结构，就在**原路径上**改内容（加节点、改接线），不要改路径。

## 五、什么时候会「断」

| 你动了什么 | 后果 |
| --- | --- |
| 改 Variant 的**节点名 / 层级** | **动效断**（clip 按路径绑定）；主题 token 不受影响（target 是组件引用） |
| 改 Variant 里**图标 / 文字节点的组件**（删 `Image` / 换 `TMP_Text`） | `KitButton` 的引用变空 → 组合 token 跳过那几项（「空 = 不管」），不报错，但那部分主题失效 |
| 删掉 `TokenMatch` | 该节点不再被匹配，主题完全不生效 |
| 改匹配 id 字符串 | 与 token 库对不上 → 校验报「缺 token」，主题不生效 |
| 包内 prefab **路径改名 / 移动** | 消费者已导入的 Variant 断链 |

## 六、字体

v1 的 token **不碰字体**（`TextTokenSo` 有字体字段，但示例里没提供字体 token）：`TMP_FontAsset` 是工程资产，包内塞一个只会让别的工程引用到空资产。

包内控件的 TMP 文字指向 **TMP Essential Resources 的默认字体**（`LiberationSans SDF`，GUID `8f586378b4e144a9851e7b34d9b748ee`）—— 这个 GUID 在**任何**导入了 TMP Essential Resources 的工程里都一样，所以不会断。中文靠工程的 **fallback 字体**兜底（TMP Settings 的 fallback 列表），没配就是方块。

要指定字体：加一条 `FontAssetTokenSo`（原子）或给 `TextTokenSo` 填字体字段，挂在对应槽位上。
