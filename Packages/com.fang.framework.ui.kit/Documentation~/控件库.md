# 控件库

`com.fang.framework.ui.kit` 的机制说明：为什么是「匹配组件 + token SO + 项目 SO」，以及这套机制的边界。

## 一、运作模型

```text
包内（只读、随包升级）              工程里（你自己建、随便改）
├── 控件预制体（节点带匹配组件）     ├── Prefab Variant（引用包内控件，改 icon / 局部）
├── 匹配组件（TokenMatch）           ├── token SO（独立资产，分类型：字号类 / 颜色类…）
├── 控件组件脚本                     ├── 项目 SO（UIKitProjectSo ← 驱动者）
├── 动效 / 粒子                      │     ├── prefab 列表（扫描范围）
└── 匹配规范文档                     │     └── token 库（每条 token 自带 MatchId）
                                     └── Demo（参考用法）
```

- 改 icon：做 Prefab Variant 覆盖，**不动包内** → 包升级不覆盖你的改动。
- **主题**（颜色 / 字号 / 字体 / 图标 / 底图 / 交互态）：由项目 SO 在**编辑器期**批量写入 Variant / 你自己的预制体。**不做运行时换肤入口**。
- 同一套「匹配组件 + `token.Apply`」在运行时也能直接用（`TokenMatch.ApplyFrom(project)`），以后要运行时换肤就靠它。
- **动效是双轨的**：动效的**资产引用**同样在编辑器期落盘（组合 token 把 `UiMotionSo` 写进 `KitButton` 的字段），但**播放**必须在运行时。见 `动效.md`。

## 二、闭环调用链

```text
FangHub → 控件库 → 全体应用 / 条目行「应用」   ← 编辑器期，预览确认后落盘
 └─ UIKitApplier.Build(project, onlyMatchId)
     └─ 遍历 project.Prefabs → 找 TokenMatch → 逐条取 project.GetTokens(entry.Id)
         └─ UIKitApplier.Apply(plan) → token.Apply(target) → 写回预制体资产

运行时（可选，自己驱动）
 └─ match.ApplyFrom(project)                       ← 传入项目 SO 自己
     └─ 逐条：tokens = project.GetTokens(entry.id)  ← 按 MatchId 查 token 库
         └─ 逐个 token.Apply(entry.target)         ← 传入 target
             └─ 规则作用于 target（写值 / 确保组件 / 接线）
```

## 三、匹配组件 `TokenMatch`

挂在物体上，条目是**列表**：

```text
物体 A
├─ TMP_Text
├─ Image
└─ TokenMatch
     entries:
       [0] id = Text/Title     target = (本物体上的 TMP_Text)
       [1] id = Color/Primary  target = (本物体上的 Image)
```

- **一个通用组件**，不是每种控件一个 —— 否则同一物体上要挂多个组件，还会互相打架。
- Unity 不允许同一组件挂两次，所以条目必须是**列表**。
- 每条 = **`id`（匹配 id）+ `target`（组件引用）**。
- `target` 显式指定 ⇒ **不用猜组件类型**；同一物体上多个 `Graphic` 天然区分（两条各指各的）；`target` 为空 / 类型不符，校验能直接报出来。
- 包内预制体自带匹配组件；你自己造的预制体自己挂，**不用去任何中央表登记**。
- 条目在 Inspector 里编：id 可手填，也可点「选择…」按「项目 SO ▸ token 类型 ▸ MatchId」挑（下拉只是候选，**写下去的还是字符串**，预制体与项目 SO 之间不建立引用）。

## 四、token SO

- 只需要**一个方法**：`Apply(Component target)` —— 按自己的类型强转并写值，类型不符就报错。
- 基类是 `TokenSo`。包内**不提供** token 实例（那是工程资产），只提供类。
- 分**原子**与**组合**两类：

### 原子 token：一个 token 只写一个属性

| 类 | target | 写什么 |
| --- | --- | --- |
| `FontAssetTokenSo` | `TMP_Text` | 字体 |
| `FontSizeTokenSo` | `TMP_Text` | 字号 |
| `FontStyleTokenSo` | `TMP_Text` | 样式 |
| `LineSpacingTokenSo` | `TMP_Text` | 行距 |
| `ColorTokenSo` | `Graphic` | 颜色 |

要「只改字体」就只放一个字体 token，字号 / 样式 / 行距完全不碰。

### 组合 token：一个 token 管一个控件的多个属性

| 类 | target | 写什么 |
| --- | --- | --- |
| `TextTokenSo` | `TMP_Text` | 字体 / 字号 / 样式 / 行距 / 颜色（**逐项开关**） |
| `IconTokenSo` | `Image` | Sprite / 颜色（颜色带开关） |
| `ButtonTokenSo` | `KitButton` | 底图 Sprite / 5 态 `ColorBlock` / **嵌套**文字 token + 图标 token / 两个动效槽位 |

原子与组合**都保留**，按槽位选一种用（见 `匹配规范.md` §二 的按钮组）。

### 组合 token 与嵌套

组合 token 怎么找到「按钮上的文字」和「按钮上的图标」？靠 `KitButton` 上的**显式引用**，不靠名字查找：

```text
KitButton（结构契约）        底图 / 按钮本体 / 图标 / 文字 → 只读
                             两个动效槽位（Click / Locked） → 可写
   ↑ target
ButtonTokenSo（组合）        嵌 TextTokenSo + IconTokenSo，
                             把 KitButton.Label / Icon 递给内层
   ├── TextTokenSo（组合）    值 + 写值逻辑
   └── IconTokenSo（组合）    值 + 写值逻辑
```

规则：

- **嵌套限一层**：被嵌套的 token 自己不再嵌。
- **被嵌套的子 token 不登记进 token 库、`MatchId` 留空**，只被外层引用、不参与匹配。所以 `TokenMatchValidator` 不会误报「缺 token」，`UIKitApplier` 也不会独立匹配它。
- **外层必须判空再调内层**：纯图标按钮上 `KitButton.Label` 是 `null`，纯文字按钮上 `KitButton.Icon` 是 `null`。直接调内层会让 `EnsureTarget(null)` 报 `LogError`。
- 三种按钮共用**一个** `KitButton` 类 + **一个** `ButtonTokenSo` 类，靠**可空引用**区分：

| 预制体 | `Background` | `Icon` | `Label` |
| --- | --- | --- | --- |
| 图标按钮 | ✓ | ✓ | `null` |
| 文本按钮 | `null` | `null` | ✓ |
| 图标+文本按钮 | ✓ | ✓ | ✓ |

  空就是空，全程不涉及名字查找。**为什么不在类层面拆成三个**：三种结构是**包含关系**，底图 / 按钮本体 / 5 态 / 触发机制完全一样；拆开 = 三份重复代码，加第四种组合还要再加一类。差异靠**不同的 token 资产**表达，不靠不同的类。
- 只有按钮需要 `KitButton`：`TextTokenSo.TargetType = TMP_Text`、`IconTokenSo.TargetType = Image`，文字和图标各自都在**一个**组件上，一个 target 就够；按钮**跨节点**（底图 / 图标 / 文字在三个节点上），才需要一个组件当结构契约。
- **动效为什么放在 `KitButton` 上**：颜色 / 字号 / 图标 Sprite 直接写 Unity 的 `Image` / `TMP_Text`，它们本来就有位置；**动效没有原生宿主**，需要一个组件存它，而 `KitButton` 正好已经在。

### 写值语义：空 = 不管

**引用为空时 `Apply` 必须跳过，不能把 target 写成 null。** 否则「全体应用」会把用户手配的值（尤其是动效）清掉。

这条语义顺带把「逐项开关」统一掉：

| 字段类型 | 怎么表示「不写」 |
| --- | --- |
| **值**（`Color` / `float` / `FontStyles` / `ColorBlock`） | 需要 `bool` 开关 —— 值永远有值，没法用空表示 |
| **引用**（`TMP_FontAsset` / `Sprite` / `TokenSo` / `UiMotionSo`） | **空 = 不写**，不需要开关 |

所以 `TextTokenSo` 只有字号 / 样式 / 行距 / 颜色要开关；`IconTokenSo` 只有颜色要开关；`ButtonTokenSo` 只有 `ColorBlock` 要开关。

### 组合 token 的已知代价

| 代价 | 原因 |
| --- | --- |
| **预览粒度变粗** | `UIKitApplier` 按 `TokenMatch` 条目列「将被改的」，嵌套效果只显示成「`Button/Primary` 被应用」，看不到具体改了哪几个属性 |
| **FangHub token 库看不到嵌套 token** | 页面只列 `project.Tokens` |
| **`MatchId` 留空有两个含义** | 「还没启用」与「只被引用」（见下） |
| **图标和文字必须是两个节点** | 同物体上多个 `Graphic` 共用同一个 `CanvasRenderer`，`SetMesh` / `SetMaterial` 互相覆盖 |

- 每个 token 身上有两个「id」，**别混**：

| 字段 | 是什么 | 谁在用 |
| --- | --- | --- |
| `MatchId`（`TokenSo._matchId`） | **匹配 id**，即连接键：`Text/Title`（**手填字符串，没有枚举/常量表**） | 匹配：预制体端条目的 id ↔ 这条 token |
| `Id`（`ConfigDataSo._id`） | 资产自己的标识（= 资产名） | 标识资产本身，**绝不当匹配 id 用** |

- `MatchId` 留空有**两种**含义，都表示「不参与匹配」：① 这条 token **还没启用**（你还没配）；② **只被引用** —— 组合 token 嵌套的子 token 也留空（见上面的「组合 token 与嵌套」）。两种都只给提醒，不算问题。
- `MatchId` 是自由字符串，**拼错不会报错** —— 校验只会告诉你「这个 id 在 token 库里没有 token」，靠 `Documentation~/匹配规范.md` 的推荐命名对齐。

## 五、项目 SO `UIKitProjectSo`

- `prefab 列表` ← 全体应用的**扫描范围**（你的 Variant + 你自己的控件）。
- `token 库`：直接一个 `List<TokenSo>`（**没有中间的绑定行**）。匹配 id 就写在每条 token 的 `MatchId` 上，所以表里不再写一遍 id。
- `GetTokens(id)`：按 `token.MatchId == id` 过滤，**按 token 库里的顺序**返回。
- **同一个 id 上可以挂多个 token**（例如 `Text/Title` 同时挂字号 token 和颜色 token）：应用时**依次 `Apply`，后面的覆盖前面的**，这**不算错误、也不去重**。若两个 token 写同一个属性，实际生效的是排在后面的那个。
- `GetTokens(id)` 与 `TokenMatch.ApplyFrom(project)` 运行时可直接用；编辑器期的批量落盘由 `UIKitApplier` 负责（见 §九）。

## 六、规则的动作类型

规则拿到的是 `target`（组件），所以从 `target.gameObject` 就能做的不止「写值」：

| 动作 | 干什么 |
| --- | --- |
| **写值** | 改 `target` 的属性（字号 / 颜色…） |
| **确保组件** | 匹配到的节点上没有就 `AddComponent`，有就跳过（**幂等**） |
| **确保组件 + 接线** | 加上之后把它的某个字段指向 `target`（如闪光特效的 `targetText` ← 那个 `TMP_Text`） |

约束：

- **结构动作必须排在写值之前**（否则值没地方写）⇒ 规则分两阶段（先结构、后值）或带顺序号。
- **不做删组件** —— 加是幂等的、安全的；删可能删掉你自己的东西。
- **Variant 上加组件合法** —— Unity 支持「Variant 加组件」作为 override，照样**不动包内**。
- 接线目标默认就是本次匹配的 `target`；要指向别的节点得另定查找方式。

## 七、边界

- 规则**只碰它声明的那几项**（写哪些属性 / 加哪个组件 / 接哪根线）；用户手改的其它属性（icon、位置、尺寸）不受影响。
- **同一属性**若用户手改过，下次全体应用会被覆盖 ⇒ 需要明确「这个属性归 token 管」。同一 id 上多个 token 写同一属性时，**按 token 库顺序，后面的赢**。
- **包内只读** ⇒ 全体应用只改得到工程里的（Variant 覆盖 + 你自己的预制体）；直接用包内预制体（没做 Variant）的，主题管不到，会停在默认值。
- **不做撤销** ⇒ 全靠 git 回退；因此**预览是必需项**（列出将被改的 prefab / 节点 / 条目，以及每条被跳过的原因），确认后才落盘。
- 写回走 `PrefabUtility.LoadPrefabContents` / `SaveAsPrefabAsset`：**变体关系保留、基预制体零改动、改动记成 Variant 的 override**（已实测）。
- 同物体上多个 `Graphic` 会**共用同一个 `CanvasRenderer`**（`Graphic.canvasRenderer` 就是 `GetComponent<CanvasRenderer>()`），各自 `SetMesh` / `SetMaterial` 会互相覆盖 ⇒ 图标与文字仍建议拆成两个节点。
- TMP 字体覆盖：`text.font = fontAsset` 会**同时**把 `m_fontAsset` 与 `m_sharedMaterial` 写进预制体，不需要手动补材质。
- **9 宫格底图的 `border` 决定控件的最小尺寸**（实测踩过）：`Image` 在 `Sliced` 类型下的 `preferredWidth/Height` 就是 `border` 的四边之和，而按钮根上的 `ContentSizeFitter` 取的是**最大值** —— 所以底图 border 太大时，按钮**压不到设计高度**。包内 `Sprites/ButtonBackground.png` 的 border 是 10（四边和 20），32 高的按钮才成立；原来 border 20（四边和 40）时按钮实测卡在 40 高，改字号和 padding 都没用。

### 动效要求的结构：`LayoutGroup` 会覆盖动效

`HorizontalLayoutGroup` / `VerticalLayoutGroup` 会**写子节点的 `anchoredPosition` 和尺寸**，而「图标飞入」这类动效动的正是 `anchoredPosition` —— 会被覆盖；`ContentSizeFitter` 还会让尺寸随内容变、触发 Rebuild，覆盖更频繁。

所以包内控件的按钮是**给动效留了中间节点**的：

```text
ButtonIconText (root: RectTransform + Image + Button + KitButton + TokenMatch
                     + HorizontalLayoutGroup + ContentSizeFitter)
├── IconSlot   (RectTransform + LayoutElement)   ← LayoutGroup 控制这个（尺寸固定）
│   └── Icon   (RectTransform + Image)           ← 动效驱动这个（自由）
└── LabelSlot  (RectTransform + LayoutElement)
    └── Label  (RectTransform + TMP_Text)        ← 动效驱动这个（自由）
```

- `KitButton` 的 `Icon` / `Label` 指向**内层** —— 换 Sprite / 颜色和动效都作用在内层。
- 容器自己弹变形（如点击缩放）作用在 root 的 `scale`，**不受 `LayoutGroup` 影响**。
- 代价是多一层嵌套；换来的是「改文字长度」不用手调位置，且动效不会被布局覆盖。

### 「包内预制体主题管不到」在 demo 里怎么示范

全体应用只改得到**工程里的**资产，所以 demo 的链路是：

1. 包内 `Prefabs/ButtonIconText.prefab` 是**基预制体**（节点结构 + `KitButton` / `TokenMatch` 接线），不登记进项目 SO。
2. demo 在 `Samples~/Demo/Prefabs/` 下做了 6 个 **Prefab Variant**，项目 SO 的 `Prefabs` 列表登记的是**这些 Variant**。
3. demo 场景里放的是**这些 Variant 的实例**，所以「全体应用」写进 Variant 后，场景跟着变。
4. 直接用包内预制体（不做 Variant）的控件，主题**管不到**，会停在默认值 —— 这就是「只读」的机制后果，不是 bug。

## 八、匹配 id

见 `匹配规范.md`。`id` 是**手填字符串**，推荐形状 `<组>/<语义>`（`Text/Title`、`Color/Primary`），落在 **token 的 `MatchId`** 上。

## 九、编辑器入口

`Tools/Fang Framework/Fang Hub → 控件库`（页 id `framework-ui-kit`）：

| 位置 | 干什么 |
| --- | --- |
| 菜单栏「控件库项目 ▾」 | 新建项目配置 SO / 选工程里已有的项目 |
| 菜单栏「统计」 | 按 token 类型列出 token 库里的全部匹配 id |
| 菜单栏「校验」 | 项目 SO + 所有登记预制体的 `TokenMatch` 一起校验（问题与提醒分开列） |
| 菜单栏「全体应用」 | 预览 → 确认 → 落盘（范围 = 全项目） |
| 左列顶部 | `组件库` / `token 库` 切换 |
| 左列列表头 `＋` | 组件库 → 空壳预制体引导向导；token 库 → 新 token 引导向导（选类型 + 逐项填字段 + **手填匹配 id** + 资产名 + 位置） |
| 右详情 | 基本信息（默认折叠）/ 资产路径 + 定位 / 完整性或校验 / 条目列表（每条带「应用」= 只应用该 id）/ 内嵌可编辑 Inspector |
