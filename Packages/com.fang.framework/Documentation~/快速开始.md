# 快速开始

## 一、引用

`Runtime/Fang.Framework.asmdef` 的 `autoReferenced` 为 `true`，`Assets/` 下的预定义程序集（`Assembly-CSharp`）可直接使用：

```csharp
using Fang.Framework;
```

如果代码位于自定义 asmdef 中，需要在 asmdef 的 `references` 里加上 `Fang.Framework`。

## 二、定义领域

```csharp
using Fang.Framework;
using UnityEngine;

public sealed class ItemConfigDataSo : ConfigDataSo
{
    [SerializeField] private int _maxStack;
    [SerializeField] private int _baseDamage;

    public int MaxStack => _maxStack;
    public int BaseDamage => _baseDamage;
}

public sealed class ItemData : Data<ItemConfigDataSo>
{
    private int _count;
    private int _durability;

    public ItemData(ItemConfigDataSo config) : base(config)
    {
        _count = 1;
        _durability = config.BaseDamage;
    }

    public int Count => _count;
    public int Durability => _durability;

    public void Add(int amount)
    {
        _count = Mathf.Clamp(_count + amount, 0, Config.MaxStack);
    }

    public void ApplyDamage(int amount)
    {
        _durability = Mathf.Max(0, _durability - amount);
    }
}

public sealed class ItemController : Controller<ItemConfigDataSo, ItemData>
{
    public void Use(int amount)
    {
        Data.ApplyDamage(amount);
    }
}

public sealed class ItemWorldObject : WorldObject<ItemController, ItemData, ItemConfigDataSo>
{
}
```

要点：

- 配置字段是 `private [SerializeField]`，对外只有只读属性。写配置走 `SerializedObject` / `SerializedProperty` + `EditorUtility.SetDirty`。
- `Data` 只有带参构造，`Config` 在构造时就位。
- `Data` 自己的状态由自己的方法改（`Add` / `ApplyDamage`），不变量在方法里守。
- **`Controller` 是纯 C# 类**，不是 `MonoBehaviour`；只有 `ItemWorldObject` 挂在 GameObject 上。

## 三、定义能力

```csharp
using Fang.Framework;

public sealed class InventoryService : Service
{
    private readonly List<ItemData> _items = new List<ItemData>();

    public override void OnInit()
    {
    }

    public override void OnDispose()
    {
        _items.Clear();
    }

    public void Add(ItemData item)
    {
        _items.Add(item);
    }
}
```

`Service` 本身没有抽象成员，只提供 `OnInit` / `OnDispose` 的空实现和注入好的 `Scope`。需要每帧能力的服务自己挂接口：

```csharp
public sealed class SpawnerService : Service, ITickable
{
    public void OnTick(float deltaTime)
    {
    }
}
```

`OnInit` / `OnDispose` 是 `virtual`，覆盖时才写 `override`。

## 四、定义 Scope

`Scope` 是抽象类，`AddService` / `CreateChildScope` / `RemoveService` 是 `protected` —— 装配由具体 `Scope` 子类负责，外部只通过 `GetService<T>()` 取用。

```csharp
using Fang.Framework;

public sealed class GameScope : Scope
{
    public InventoryService Inventory { get; private set; }

    public void Setup()
    {
        Inventory = AddService<InventoryService>();
        AddService<SpawnerService>();
    }
}
```

`AddService<T>()` 一步完成创建与托管：`new T()` → `Inject(this)` → 入表 → `OnInit()`。**没有 `Build()` 阶段，也没有就绪门槛**，`AddService` / `RemoveService` 随时可用。

## 五、驱动

框架**不提供宿主 MonoBehaviour**，使用方自己写：

```csharp
using Fang.Framework;
using UnityEngine;

public sealed class GameScopeHost : MonoBehaviour
{
    private GameScope _scope;

    private void Awake()
    {
        _scope = new GameScope();
        _scope.Setup();
    }

    private void Update()
    {
        _scope.Tick(Time.deltaTime);
    }

    private void FixedUpdate()
    {
        _scope.FixedTick(Time.fixedDeltaTime);
    }

    private void OnDestroy()
    {
        _scope.Dispose();
    }
}
```

- `Tick` / `FixedTick`：先自己的服务（按添加顺序），再递归子 Scope。
- `Dispose`：先逆序释放全部子 Scope，再逆序 `OnDispose` 自己的服务。幂等。
- 所有 Unity 接触面（`new GameObject`、`Instantiate`、`AudioSource`、协程）都在这一层桥接。

## 六、子 Scope

```csharp
public sealed class BattleScope : Scope
{
    public void Setup()
    {
        AddService<BattleService>();
    }
}

public sealed class GameScope : Scope
{
    public BattleScope Battle { get; private set; }

    public void Setup()
    {
        Battle = CreateChildScope<BattleScope>();
        Battle.Setup();
    }
}
```

树形与解析：

```text
GameScope
├── InventoryService
├── SpawnerService
└── BattleScope
    └── BattleService
```

- 本层 miss → 沿 `_parent` 一路向上，任意一层命中即返回。
- 本层命中就不再向上：`GetService<T>()` 取的是**离自己最近**的那一个。
- **父 `Dispose()` 会递归释放全部子 Scope**（先逆序子，再逆序自己的服务）。

## 七、服务之间怎么互相取用

`Service` 与 `Controller` 都持有注入好的 `protected Scope`，直接调 `GetService<T>()`：

```csharp
public sealed class BattleService : Service, ITickable
{
    private InventoryService _inventory;

    public override void OnInit()
    {
        _inventory = Scope.GetService<InventoryService>();
    }

    public void OnTick(float deltaTime)
    {
    }
}
```

**零反射**：框架不按构造函数解析依赖，取用一律显式写 `Scope.GetService<T>()`。服务也不在自己的构造函数里注册自己。

## 八、异常

| 异常 | 触发场景 |
| --- | --- |
| `InvalidOperationException` | `GetService<T>()` 沿整条父链都没命中；消息里带服务类型全名与 Scope 名 |
| `ArgumentNullException` | `Controller.Initialize(null)` / `WorldObject.Initialize(null)` |

核心层不再定义自定义异常类型。

## 九、明确不做

- 框架不提供 `Entry` 启动入口、日志抽象、事件总线、资源管理、对象池。
- 框架不提供宿主 MonoBehaviour。
- 框架不做序列化 / 存档。
- `Controller` 的 tick 驱动者未定，取决于「实体挂载」的设计。
