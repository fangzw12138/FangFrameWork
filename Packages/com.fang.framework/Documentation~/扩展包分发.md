# 扩展包分发

核心包与扩展包同仓（`github.com/fangzw12138/FangFrameWork`），扩展包走 **git URL + `?path=` + tag** 分发，零基础设施。本文写清这套机制的边界、约定与用法。

## 一、路线与三个决定性事实

| 方式 | 更新检测 | 基础设施 | 采用 |
| --- | --- | --- | --- |
| UPM scoped registry | 原生支持 | 要托管 registry | 否 |
| **Git URL + `?path=` + tag** | **不支持，要自建** | 无 | **是** |
| `.tgz` | 不支持 | 要放文件 | 否 |
| 目录拷贝 / `file:` 内嵌 | 不支持 | 无 | 仅本地开发 |

选 git URL 的理由：扩展包与核心包同仓，零基础设施，是开源 UPM 包的主流形态（UniTask / VContainer / R3 同）。代价是更新检测得自己写 —— 这正是 `Tools/Fang Framework/Extension Packages` 窗口存在的唯一理由。

### 事实 1：Unity 不检测 git 依赖更新

git 依赖解析一次后锁进 `Packages/packages-lock.json`（官方称 "Locked Git dependencies"）。升级只能重新 `Client.Add` 一个**新的 tag 或 SHA**，UPM 不会因为远端 tag 指向变了就重装。

**结论：版本比对必须由窗口自己做**（读索引里的 `version` vs 本地 `PackageInfo.version`）。

### 事实 2：UPM 不支持包内声明 git URL 依赖

扩展包的 `package.json` 若写：

```json
"dependencies": { "com.fang.framework": "0.4.0" }
```

在「核心包来自 git URL / 内嵌」的工程里会解析失败 —— 没有 registry 能回答 `com.fang.framework` 的 `0.4.0` 在哪。

**结论：扩展包的 `dependencies` 留空对象**，依赖关系靠三件事落地：

1. asmdef 的 `references`（`Fang.Framework.EventBus` 引用 `Fang.Framework`）—— 编译期真实生效；
2. 安装窗口的前置检查（核心包未装时禁用全部安装按钮）；
3. 扩展包 `README.md` 里的显式声明。

### 事实 3：git 依赖需要本机 git CLI

UPM 用本机 git 拉取。请求失败时窗口把 UPM 的**原始错误原文**显示到状态区，不吞错。

## 二、版本与 tag 约定

```text
核心包     com.fang.framework            tag: com.fang.framework/v0.4.2
扩展包     com.fang.framework.eventbus   tag: com.fang.framework.eventbus/v0.1.0
```

- **每包独立 tag**，格式 `<包名>/v<version>`，与对应 `package.json` 的 `version` 一一对应。OpenUPM 对 monorepo 就推荐这种前缀 tag（`com.example.package/v1.2.3`）。
- tag 里的 `/` 不是问题：Unity 把 `#` 之后整串原样交给 git。
- **不用仓库级统一 tag**（如 `v0.4.0`）：那会把所有包绑死在同一版本上，任何一个包改动都要全体升版本。每包独立发布、独立升级。
- 改完某个包 → 升它的 `package.json` `version` → 改仓库根 `packages.json` 里对应条目的 `version` / `tag` → 提交 → 打 tag → push。

## 三、索引文件 `packages.json`

放在**仓库根**。放 `Packages/` 下会跟着包一起被打进 UPM 包，不合适。

```json
{
  "repository": "https://github.com/fangzw12138/FangFrameWork.git",
  "core": {
    "name": "com.fang.framework",
    "displayName": "Fang Framework",
    "path": "/Packages/com.fang.framework",
    "version": "0.4.2",
    "tag": "com.fang.framework/v0.4.2"
  },
  "packages": [
    {
      "name": "com.fang.framework.eventbus",
      "displayName": "Event Bus",
      "description": "类型安全发布订阅。",
      "path": "/Packages/com.fang.framework.eventbus",
      "version": "0.1.0",
      "tag": "com.fang.framework.eventbus/v0.1.0",
      "unity": "2022.3"
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `repository` | 仓库地址。缺 `.git` 时窗口自动补；`git+file://` 原样使用 |
| `core` | 核心包单列一条，窗口用它做前置检查 |
| `packages[].name` | 包名，与 `package.json` 的 `name` 一致 |
| `packages[].path` | 包在仓库里的目录，前导 `/` 可省（窗口自动补） |
| `packages[].version` | 与包内 `package.json` 的 `version` 一致，窗口用它比版本 |
| `packages[].tag` | 安装时 `#` 后面的那一段 |
| `packages[].unity` | 最低引擎版本，仅展示用 |

- 用 Unity 自带 `JsonUtility` 解析（零第三方依赖）。`JsonUtility` 不支持根数组，所以索引是对象；DTO 是 `[Serializable]` 类。
- 缺 `repository`、缺 `core.name` → 整个索引判为非法；某条 `packages` 缺 `name` / `path` / `tag` → 只丢这一条。
- **索引手写维护**，暂不做自动生成。
- 索引格式刻意与「将来换成 scoped registry」兼容：换源时窗口逻辑不用动。

## 四、窗口

`Tools/Fang Framework/Extension Packages`

```text
索引地址 [ https://raw.githubusercontent.com/…/packages.json ]  [刷新索引]
核心包：已装 0.4.0（Git）
状态：索引已更新：1 个扩展包。
┌──────────────────────────────────────────────────────────────────────┐
│ Event Bus  com.fang.framework.eventbus   索引 0.1.0 / 本地 未装   [安装] │
└──────────────────────────────────────────────────────────────────────┘
```

- **索引地址**存在 `EditorPrefs`（`Fang.Framework.ExtensionPackages.IndexUrl`）。`https://` 走 `UnityWebRequest`，`file://` 直接读本地文件（离线验证用）。
- **核心包行**显示本地核心包版本与来源（`Embedded` / `Git` / `Registry`）。核心包未装时全部安装按钮禁用 —— 扩展包依赖核心包。
- **每行状态**：

| 状态 | 判据 | 按钮 |
| --- | --- | --- |
| 未装 | 本地查无此包 | 安装 |
| 已是最新 | 索引版本 == 本地版本 | 卸载 |
| 可更新 | 索引版本 > 本地版本 | 更新 |
| 本地领先 | 本地版本 > 索引版本（开发中） | 卸载 |
| 内嵌 | `PackageInfo.source == Embedded`（本仓库开发场景） | 无按钮 |

- 更新走的就是 `Client.Add`：对已装同名包，UPM 的行为是**替换 source**，Unity 自己重写 `packages-lock.json`。
- 操作进行中（`IsBusy`）时全部按钮禁用，避免并发请求。
- 版本比较是语义化比较：数字段逐段比（缺段补 0），数字全等时比 pre-release（`0.1.0` > `0.1.0-preview.1`）。

## 五、其他工程怎么装

### 方式一：安装窗口（推荐）

1. 装核心包（见下）。
2. `Tools/Fang Framework/Extension Packages`。
3. 索引地址保持默认（raw 直链），点「刷新索引」。
4. 点「安装」。

### 方式二：手写 `Packages/manifest.json`

```json
{
  "dependencies": {
    "com.fang.framework": "https://github.com/fangzw12138/FangFrameWork.git?path=/Packages/com.fang.framework#com.fang.framework/v0.4.2",
    "com.fang.framework.eventbus": "https://github.com/fangzw12138/FangFrameWork.git?path=/Packages/com.fang.framework.eventbus#com.fang.framework.eventbus/v0.1.0"
  }
}
```

两种方式等价，都需要本机 git CLI。装完 `Packages/packages-lock.json` 里会多出 `"source": "git"` 的两条。

**升级**：改 URL 里的 tag（或重新 `Client.Add` 新 tag）。UPM 不会自动发现新版本，这也是窗口存在的原因。

## 六、本地离线验证

不需要 push 就能验证整条链路：

1. 提交扩展包目录。
2. 本地打 tag（`git tag com.fang.framework.eventbus/v0.1.0`，**不 push**）。
3. 把工程里内嵌的扩展包目录移出 `Packages/`（否则同名包会判为内嵌，窗口不给按钮）。
4. 窗口索引地址填 `file:///D:/GameProjects/FangFrameWork/packages.json`。
5. 索引里 `repository` 填 `git+file:///D:/GameProjects/FangFrameWork`。
6. 窗口点「安装」→ Console 零错误、`Fang.Framework.EventBus` 程序集可用 → 点「卸载」→ 工程还原干净。

验证完删掉本地 tag、还原工程即可。

## 七、明确不做

- OpenUPM / 自建 registry（索引格式刻意与「换成 registry」兼容）。
- 扩展包之间的依赖解析、版本范围、冲突仲裁。
- 索引自动生成（GitHub Actions / 发布脚本）。
- 安装进度条、取消、下载缓存加速、镜像源。
- 多页工作台、Domain 脚本脚手架、项目初始化、创建空扩展包骨架。
