# 目录规范

## 一、包结构

```text
Packages/com.fang.framework/
├── package.json
├── README.md
├── CHANGELOG.md
├── LICENSE.md
├── Documentation~/                  目录名带 ~ 后缀，不参与 Unity 导入
│   ├── 架构总览.md
│   ├── 快速开始.md
│   ├── 表现层规范.md
│   ├── 扩展包分发.md
│   ├── 目录规范.md
│   ├── 编码规范.md
│   └── AI约束.md
├── Runtime/
│   ├── Fang.Framework.asmdef
│   └── Core/                        ← 框架核心（全部）
│       ├── ILifecycle.cs            ILifecycle / ITickable / IFixedTickable
│       ├── Scope.cs                 IInjectable + Scope（MonoBehaviour）
│       ├── Service.cs               Service（MonoBehaviour）
│       └── Domain/                  ← 三件套领域
│           ├── ConfigDataSo.cs      ScriptableObject
│           ├── Data.cs              纯 C#
│           └── Controller.cs        MonoBehaviour
├── Editor/
│   ├── Fang.Framework.Editor.asmdef
│   ├── FangEditorPrefs.cs            工程 token + EditorPrefs 键前缀（Hub 布局与页面状态共用）
│   ├── ExtensionPackageIndex.cs      索引 DTO + 解析 + URL 拼装 + 状态判定（纯逻辑）
│   ├── ExtensionPackageCatalog.cs    包列表的筛选 / 搜索 / 行状态 / 描述取值（纯逻辑）
│   ├── ExtensionPackageInstaller.cs  Client.List/Add/Remove 轮询状态机（纯逻辑）
│   └── Hub/
│       ├── FangHubPageAttribute.cs         页面注册属性
│       ├── IFangHubPage.cs                 页面基础接口
│       ├── IFangHubImGuiPage.cs            IMGUI 渲染能力接口
│       ├── IFangHubVisualElementPage.cs    UI Toolkit 渲染能力接口
│       ├── FangHubPageDescriptor.cs        扫描结果（元数据 + PageType）
│       ├── FangHubGroupView.cs             侧栏渲染用的视图模型
│       ├── FangHubPageRegistry.cs          TypeCache 扫描 + 视图构建（纯逻辑）
│       ├── FangHubLayout.cs                布局模型 + 纯逻辑增删改
│       ├── FangHubLayoutStore.cs           布局持久化（JsonUtility ↔ EditorPrefs）
│       ├── FangHubPageState.cs             页面状态存储
│       ├── FangHubWindow.cs                窗口本体（唯一接触 UI 的地方）
│       └── Pages/
│           └── ExtensionPackagesPage.cs    内置「框架与扩展」页 / 包中心（UI Toolkit）
└── Tests/
    ├── Runtime/
    │   ├── Fang.Framework.Tests.asmdef
    │   ├── ScopeTestDoubles.cs
    │   ├── DomainContractTests.cs
    │   ├── ScopeRegistrationTests.cs
    │   ├── ScopeHierarchyTests.cs
    │   └── ScopeLifecycleTests.cs
    └── Editor/
        ├── Fang.Framework.Editor.Tests.asmdef
        ├── ExtensionPackageIndexTests.cs
        ├── ExtensionPackageCatalogTests.cs
        ├── FangHubLayoutTests.cs
        ├── FangHubPageRegistryTests.cs
        └── FangHubPrefsTests.cs
```

`Runtime/` 下只留一层 `Core/` —— **框架核心全部收在这里**，三件套领域作为它的 `Domain/` 子层。不按类型平铺目录（不设 `Runtime/Scope/`、`Runtime/Service/`）。表现层不进核心包（见 `表现层规范.md`）。

`Editor/` 按「纯逻辑 / 接触 UI」分层：索引解析、包列表的筛选 / 搜索 / 行状态、安装状态机、Hub 的扫描 / 布局 / 持久化都不碰 UI（可单测），只有 `FangHubWindow` 与 `ExtensionPackagesPage` 接触 UI。窗口用 UI Toolkit 纯 C# 建树，不引 UXML / USS；`UnityEngine.UIElements` 是引擎内置模块，不算第三方依赖。Hub 的完整说明见 `FangHub.md`。

## 二、程序集

| asmdef | 程序集名 | 平台 | 说明 |
| --- | --- | --- | --- |
| `Runtime/Fang.Framework.asmdef` | `Fang.Framework` | 全平台 | `autoReferenced: true` |
| `Editor/Fang.Framework.Editor.asmdef` | `Fang.Framework.Editor` | Editor | 索引 / 安装编排 / FangHub；扩展包要挂 FangHub 页面时，其 Editor asmdef 的 `references` 必须显式列出 `Fang.Framework.Editor` |
| `Tests/Runtime/Fang.Framework.Tests.asmdef` | `Fang.Framework.Tests` | Editor | `testAssemblies: true`，`UNITY_INCLUDE_TESTS` |
| `Tests/Editor/Fang.Framework.Editor.Tests.asmdef` | `Fang.Framework.Editor.Tests` | Editor | `testAssemblies: true`，`UNITY_INCLUDE_TESTS` |

`autoReferenced: true` 是**必需**的：工程 `Assets/` 下若没有 asmdef，业务代码落在预定义程序集 `Assembly-CSharp` 中，只有 `autoReferenced` 为 true 的 asmdef 才会被它自动引用。

## 三、扩展包机制

`Packages/` 下可并列多个包：核心包 `com.fang.framework` + 若干可选扩展包。

| 扩展包 | 内容 |
| --- | --- |
| `com.fang.framework.serialization` | 序列化抽象（格式可插拔）+ 零依赖默认实现 |
| `com.fang.framework.saveload` | 存档驱动：槽位、分段、区块文件、原子写 |
| `com.fang.framework.eventbus` | 类型安全发布订阅 |
| `com.fang.framework.objectpool` | 对象池 |
| `com.fang.framework.ui` | UI 面板：UGUI 与 UI Toolkit 双轨、面板栈、层排序、跟随面板 |

**依赖只有单向：扩展包引用核心包，核心包永不引用扩展包。**

扩展包的程序集命名沿用同一前缀（如 `Fang.Framework.Serialization`），命名空间前缀 `Fang.Framework.Serialization`。

### 3.1 仓库布局

```text
<仓库根>/
├── packages.json                     扩展包索引（放仓库根，不跟着包打进 UPM 包）
└── Packages/
    ├── com.fang.framework/           核心包
    └── com.fang.framework.xxx/       扩展包，与核心包平级
```

### 3.2 单个扩展包的结构

```text
Packages/com.fang.framework.eventbus/
├── package.json                      name / version / displayName / unity；dependencies 为空对象
├── README.md / CHANGELOG.md / LICENSE.md
├── Documentation~/事件总线.md          设计理由
├── Runtime/
│   ├── Fang.Framework.EventBus.asmdef  references: ["Fang.Framework"]
│   └── EventBus.cs
├── Editor/                            可选：挂 FangHub 页面时才需要
│   ├── Fang.Framework.EventBus.Editor.asmdef  references: ["Fang.Framework", "Fang.Framework.Editor"]
│   └── EventBusPage.cs                 打 [FangHubPage(...)] 的页面，写法见 FangHub.md
└── Tests/Runtime/
    ├── Fang.Framework.EventBus.Tests.asmdef
    └── EventBusTests.cs
```

扩展包目录名 = 包名；程序集 = `Fang.Framework.<领域>`；命名空间 = `Fang.Framework.<领域>`。扩展包的程序集 `autoReferenced: true`，与核心包一致。Editor 侧程序集命名 `Fang.Framework.<领域>.Editor`，`includePlatforms: ["Editor"]`。

### 3.3 依赖怎么落地

UPM **不支持包内声明 git URL 依赖**（详见 `扩展包分发.md` §一 事实 2），所以扩展包的 `dependencies` 是空对象，依赖靠三件事：

1. asmdef 的 `references` —— 编译期真实生效；
2. FangHub「框架与扩展」页的前置检查 —— 核心包未装时禁用全部安装按钮；
3. 扩展包 `README.md` 的显式声明。

### 3.4 版本与 tag

每包独立 tag，格式 `<包名>/v<version>`，与包内 `package.json` 的 `version` 一一对应：

```text
com.fang.framework/v0.5.1
com.fang.framework.eventbus/v0.1.0
```

不用仓库级统一 tag —— 那会把所有包绑死在同一版本上。索引文件 `packages.json` 里每条目的 `version` / `tag` 与包内 `package.json` 保持一致，窗口靠它比对版本。

## 四、工程内验证沙盒

```text
Assets/Sandbox/
├── Sandbox.asmdef                    引用 Fang.Framework
└── SandboxScopeDemo.cs
```

沙盒用于验证「`Assets/` 下的代码能否直接使用框架 API」，**不进包**。包拆分为独立 Git 仓库时沙盒不随之迁移，因此测试程序集**不得引用沙盒**。

## 五、命名

| 项 | 规则 |
| --- | --- |
| 包名 | `com.fang.framework` |
| 命名空间 | `Fang.Framework` |
| 程序集 | `Fang.Framework`（与命名空间一致） |
| 配置资产 | `XxxConfigDataSo` |
| 数据 | `XxxData` |
| 逻辑 | `XxxController` |
| 表现 | `XxxVisual`（视觉脚本）/ `XxxIWO`（视图句柄），不进核心包 |
| 能力 | `XxxService` |
| 容器 | `XxxScope`（继承 `Scope`） |
| 测试 | `XxxTests` |

## 六、文件与类型对应

- 一个文件一个公开类型，文件名与类型名一致（泛型基类去掉泛型参数：`Data.cs` 放 `Data<TConfig>`）。
- 语义上不可分割的一组类型可以合并进一个文件：
  - `Scope.cs` 内含 `IInjectable` 与 `Scope`。
  - `ILifecycle.cs` 内含 `ILifecycle`、`ITickable`、`IFixedTickable`。
