# 目录规范

## 一、包结构

```text
Packages/com.fang.framework/
├── package.json
├── README.md
├── CHANGELOG.md
├── LICENSE.md
├── Documentation~/                  目录名带 ~ 后缀，不参与 Unity 导入
│   ├── 架构总览.md
│   ├── 快速开始.md
│   ├── 目录规范.md
│   ├── 编码规范.md
│   └── AI约束.md
├── Runtime/
│   ├── Fang.Framework.asmdef
│   └── Core/                        ← 框架核心（全部）
│       ├── ILifecycle.cs            ILifecycle / ITickable / IFixedTickable
│       ├── Scope.cs                 IInjectable + Scope（MonoBehaviour）
│       ├── Service.cs               Service（MonoBehaviour）
│       └── Domain/                  ← 四件套领域
│           ├── ConfigDataSo.cs      ScriptableObject
│           ├── Data.cs              纯 C#
│           ├── Controller.cs        MonoBehaviour
│           └── WorldObject.cs       MonoBehaviour
├── Editor/
│   └── Fang.Framework.Editor.asmdef
└── Tests/
    ├── Runtime/
    │   ├── Fang.Framework.Tests.asmdef
    │   ├── ScopeTestDoubles.cs
    │   ├── DomainContractTests.cs
    │   ├── ScopeRegistrationTests.cs
    │   ├── ScopeHierarchyTests.cs
    │   └── ScopeLifecycleTests.cs
    └── Editor/
        └── Fang.Framework.Editor.Tests.asmdef
```

`Runtime/` 下只留一层 `Core/` —— **框架核心全部收在这里**，四件套领域作为它的 `Domain/` 子层。不按类型平铺目录（不设 `Runtime/Scope/`、`Runtime/Service/`）。

## 二、程序集

| asmdef | 程序集名 | 平台 | 说明 |
| --- | --- | --- | --- |
| `Runtime/Fang.Framework.asmdef` | `Fang.Framework` | 全平台 | `autoReferenced: true` |
| `Editor/Fang.Framework.Editor.asmdef` | `Fang.Framework.Editor` | Editor | 占位，提前锁定程序集名 |
| `Tests/Runtime/Fang.Framework.Tests.asmdef` | `Fang.Framework.Tests` | Editor | `testAssemblies: true`，`UNITY_INCLUDE_TESTS` |
| `Tests/Editor/Fang.Framework.Editor.Tests.asmdef` | `Fang.Framework.Editor.Tests` | Editor | 占位，提前锁定程序集名 |

`autoReferenced: true` 是**必需**的：工程 `Assets/` 下若没有 asmdef，业务代码落在预定义程序集 `Assembly-CSharp` 中，只有 `autoReferenced` 为 true 的 asmdef 才会被它自动引用。

## 三、扩展包机制

`Packages/` 下可并列多个包：核心包 `com.fang.framework` + 若干可选扩展包。

| 扩展包 | 内容 |
| --- | --- |
| `com.fang.framework.serialization` | 序列化抽象（格式可插拔）+ 零依赖默认实现 |
| `com.fang.framework.saveload` | 存档驱动：槽位、分段、区块文件、原子写 |
| `com.fang.framework.eventbus` | 类型安全发布订阅 |
| `com.fang.framework.objectpool` | 对象池 |

**依赖只有单向：扩展包引用核心包，核心包永不引用扩展包。**

扩展包的程序集命名沿用同一前缀（如 `Fang.Framework.Serialization`），命名空间前缀 `Fang.Framework.Serialization`。

## 四、工程内验证沙盒

```text
Assets/Sandbox/
├── Sandbox.asmdef                    引用 Fang.Framework
└── SandboxScopeDemo.cs
```

沙盒用于验证「`Assets/` 下的代码能否直接使用框架 API」，**不进包**。包拆分为独立 Git 仓库时沙盒不随之迁移，因此测试程序集**不得引用沙盒**。

## 五、命名

| 项 | 规则 |
| --- | --- |
| 包名 | `com.fang.framework` |
| 命名空间 | `Fang.Framework` |
| 程序集 | `Fang.Framework`（与命名空间一致） |
| 配置资产 | `XxxConfigDataSo` |
| 数据 | `XxxData` |
| 逻辑 | `XxxController` |
| 表现 | `XxxWorldObject` |
| 能力 | `XxxService` |
| 容器 | `XxxScope`（继承 `Scope`） |
| 测试 | `XxxTests` |

## 六、文件与类型对应

- 一个文件一个公开类型，文件名与类型名一致（泛型基类去掉泛型参数：`Data.cs` 放 `Data<TConfig>`）。
- 语义上不可分割的一组类型可以合并进一个文件：
  - `Scope.cs` 内含 `IInjectable` 与 `Scope`。
  - `ILifecycle.cs` 内含 `ILifecycle`、`ITickable`、`IFixedTickable`。
