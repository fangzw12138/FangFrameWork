# 表现层规范

核心包**不提供表现层基类**。0.5.0 起 `WorldObject<TController, TData, TConfig>` 已删除，本文说明删掉之后表现层怎么写。

## 一、为什么没有 WorldObject 基类

`WorldObject` 原本承担的是「承载 `Controller` 的 MonoBehaviour 载体」：0.1.0 时 `Controller` 是纯 C# 类，必须有个 MonoBehaviour 把它挂到 GameObject 上，于是有了 WO。

0.3.0 起 `Controller` 自己就是 MonoBehaviour，载体职责随之失效。之后 WO 只剩三件事：

1. 持有 `Controller`；
2. 转发只读的 `Data` / `Config`；
3. 实现 `IInjectable`。

这三件都没有独占价值：`Controller.Data` 本来就是 `public` 只读属性，`Config` 走 `Data.Config` 一样拿得到，`Inject(Scope)` 对表现层也早就没有调用方。

子域实践也已经把它降级成纯 C# 视图句柄 —— 老工程 `Domain/CharacterModel/WorldObject/CharacterModelWorldObject.cs` 不继承任何东西，由 `CharacterModelController` 自己 `new` 出来；新版示例里的 `HeroWorldObject` 更是一个空类。

**零推测性 API**（`AI约束` 第 5 条）的判据是「当前调用方是否存在」：没有调用方、也没有独占能力，就删掉。

核心包 Domain 因此从四件套变成**三件套**：`ConfigDataSo` / `Data<TConfig>` / `Controller<TConfig, TData>`。

UI 面板基类同样不在核心包：`UIPanelController<TConfig, TData>` 与 `UIVisualTreePanelController<TConfig, TData>` 归 UI 扩展包 `com.fang.framework.ui`（见该包 `Documentation~/UI.md`）。

`Controller<TConfig, TData>` 仍是双泛型 —— `TData : Data<TConfig>` 这条约束本身就必须两个参数才表达得出来，跟 WO 无关（`架构总览.md` §四）。

## 二、表现层三件套

| 角色 | 形态 | 职责 |
| --- | --- | --- |
| 视觉脚本 `XxxVisual` | 普通 `MonoBehaviour` | 渲染、动画、音效、场景位置 |
| 视图句柄 `XxxIWO` | 纯 C# 类 | 持有表现引用，供控制器使用 |
| 挂载点 | 约定（不是类型） | 实体 root → `Presentation/Model` |

### 2.1 视觉脚本

- 挂在**实体 root** 上，是**唯一允许写 Unity 消息方法**的领域类型：`Awake` / `Start` / `Update` / `OnDestroy` / `[SerializeField]` 都写在这里。核心包的 `Scope` / `Service` / `Controller` 依旧一条都不写（`AI约束` 第 13 条）—— **Unity 接触面全部落在视觉脚本上**。
- **必须持有它所属的控制器的引用。** 没有控制器引用的视觉脚本就是飘逸脚本：拿不到 `Data` / `Config`，也没有人负责创建与释放它。
- 只读 `Data` / `Config` 做表现，**不直接调 `Data` 的修改方法**（`AI约束` 第二节）。
- 生命周期钩子沿用框架命名 **`Initialize()` / `OnDispose()`**，成对出现。不自造 `Build()` / `Setup()` / `Refresh()` 这类词汇。
- 由**控制器自己创建**（`Controller.OnInit()` 里 `AddComponent<XxxVisual>()` + `Initialize(this)`），不由管理服务代劳 —— 表现是控制器的私事。对应老工程「角色控制器在下面创建模型控制器」。

### 2.2 视图句柄（IWO）

纯 C# 类，由控制器 `new` 出来持有表现引用：root、模型根、骨骼根、挂点、渲染器。**不继承任何东西**，不实现接口，不接 `Scope`。

它的价值在「表现层级深、引用多」时：控制器不必自己摊平一堆 `Transform` 字段，拿一个 IWO 当门面即可。层级简单（只有一个方块）时不必造，加了就是空类 —— 空类不加。

### 2.3 挂载点约定

```text
实体 root              ← 视觉脚本 + 控制器
└── Presentation
    ├── Model          ← 模型内容建在 Model 下
    ├── Animation
    └── SFX
```

控制器**不反向引用视觉脚本**。表现怎么驱动：

- **状态走 `Data`** —— 视觉脚本自己读；
- **一次性命令走事件** —— 动画 / 音效 / 特效这类由控制器发 C# `event`，视觉脚本订阅。

C# 原生 `event` 就够，框架不提供任何新机制（`架构总览.md` §三）。

## 三、生命周期与销毁

| 谁 | 做什么 |
| --- | --- |
| 管理服务 | **创建 + 登记 + 释放**：`CreateHero` / `Heroes` / `RemoveHero` / `OnDispose`。**从不 `Destroy`** |
| 使用方 | 销毁物体。视觉脚本挂在实体 root 上，随 root 一起被回收 |
| 视觉脚本 | **不做任何跨对象回调**：不反向找管理服务出表，不在 `OnDestroy` 里注销自己 |

两点要分清：

1. **「释放」≠「销毁」。** 释放指的是 `OnDispose()`（钩子回调 + 出表），与 `AI约束` 第 14 条一致 —— 框架与服务都不销毁 GameObject。
2. **创建 + 登记 + 释放归管理服务，销毁归使用方。** 谁建谁销毁、销毁归使用方：管理服务只保证自己那张表是干净的，物体什么时候没的由使用方（场景层 / 关卡层）决定。

老工程 `Domain/Item/ItemFactoryService.cs` 的登记表 + `ItemController.OnDestroy` → `UnregisterWorldObject` 属于**完整形态**：物体自己知道要出表。本框架**不做**这条 —— 视觉脚本一旦反向持有管理服务，手就伸出去了，「谁都能从任何地方注销任何东西」。代价（认下）：物体被绕过管理服务直接销毁时，表里会留一个指向已销毁 `Controller` 的条目，直到 `RemoveHero` / `OnDispose` 被调。

## 四、命名与目录

| 项 | 规则 |
| --- | --- |
| 视觉脚本 | `XxxVisual` |
| 视图句柄 | `XxxIWO` |
| 控制器 | `XxxController` |
| 管理服务 | `XxxManagerService`（或按职责命名，如 `CharacterFactoryService`） |

`目录规范.md` 的命名表里，表现一行由 `XxxWorldObject` 改为 `XxxVisual`。

## 五、老工程实例

```text
Character(root)            CharacterWorldObject(旧) + CharacterController
└── Presentation           CharacterPresentationController
    ├── Model              CharacterModelController → new CharacterModelWorldObject
    ├── Animation          CharacterAnimationController
    └── SFX                CharacterSFXController
```

对照读法：

- `CharacterModelController` 是「角色模型控制器」，它在自己下面 `new CharacterModelWorldObject`（纯 C# 视图句柄，装 `ModelRoot` / `SkeletonRoot` / `PartRenderers` / `WeaponMounts`），并把 model 内容建到 `Model` 节点下；
- `Services/CharacterFactoryService.cs` 负责建 root、建 `Presentation/Model|Animation|SFX` 三级、`AddComponent<CharacterModelController>()`，然后 `Build()`；
- 旧版的 `CharacterWorldObject` 挂在 root 上，职责只有「持有 `CharacterController`」。

新版示例（`Samples~/MinimalSample`）是同一形状的最小版：

```text
Hero                       HeroController + HeroVisual
└── (Hero)                 HeroVisual 建的方块
```

`HeroManagerService.CreateHero` 建 root + 挂 `HeroController` + `Initialize` / `Inject` / `OnInit`；`HeroController.OnInit` 自己挂 `HeroVisual` 并 `Initialize(this)`。

## 六、禁止事项

- 表现**不许**直接调 `Data` 的修改方法 —— 要改走 `Controller` 的意图方法。
- `Controller` **不许**引用视觉脚本（单向依赖：`Controller → Data`）。
- 视觉脚本**不许**反向持有或回调管理服务（手不许伸出去）。
- 服务**不许** `Destroy` 物体，也**不许**替实体做登记 / 注销。
